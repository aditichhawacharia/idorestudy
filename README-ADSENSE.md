# IdoréStudy professional AdSense rebuild

IdoréStudy is now structured as a professional K-pop productivity website with one clear user journey:

1. Land on the homepage.
2. Choose a K-pop study buddy immediately.
3. Enter the matching study room at `/study?buddy=<id>`.
4. Use the timer, task list, optional media, and café controls without display ads inside the workspace.

The public pages have a restrained editorial design, clear publisher information, original study content, route-specific metadata, and crawler-readable HTML. The immersive study room keeps its more expressive K-pop visual identity because it is the product's main selling point.

This repository reduces avoidable AdSense review risks, but no codebase can guarantee approval. Google evaluates the deployed website, publisher account, live content, policy compliance, consent configuration, traffic quality, and other signals that cannot be manufactured in source code.

## What changed in version 3

### Homepage and user journey

- The homepage states immediately that IdoréStudy is a **K-pop study room**.
- A visitor can choose a buddy from the hero quick-start list or the complete 29-buddy grid.
- Every buddy card links directly to a selected room, for example `/study?buddy=1`.
- Search and group filters make the catalogue easier to scan.
- The primary navigation uses plain labels: Home, Study room, Study guides, and About.
- A visible byline, update date, publisher panel, FAQ, original explanatory content, and trust links make the page useful beyond the selector.

### Professional public design

- Replaced the previous heavy gradients, decorative icons, emoji-led headings, novelty copy, and repeated inline styling on public pages.
- Uses a neutral paper, ink, and plum design system with system UI fonts and Georgia headings.
- Body copy is at least 16px with generous line spacing and stronger contrast.
- About, Contact, Resources, legal pages, policies, article pages, navigation, footer, HTML sitemap, and 404 page share the same visual system.
- The colorful full-screen study room is intentionally preserved as a separate immersive product surface.

### Original publisher content

- The guide library now contains **21 original long-form articles**.
- Every guide is at least 600 words and includes multiple substantive sections, practical examples or prompts, publication and modification dates, a publisher byline, related internal links, and a source section.
- Topics cover focus planning, active recall, spaced practice, exam preparation, notes, reading, mathematics, vocabulary, distraction control, group study, catch-up planning, and sustainable routines.
- The homepage contains more than 900 words of static crawlable publisher content in addition to the buddy catalogue.

The uploaded third-party audit used 20 indexed articles and 600 words per article as scoring heuristics. Google does not publish those numbers as universal approval requirements. They are treated here as a content-depth target, not a guarantee or a substitute for usefulness and originality.

### Publisher trust and transparency

The site now includes:

- `/about` — publisher identity, purpose, product model, media handling, and advertising approach.
- `/editorial-policy` — writing, sourcing, updating, and corrections standards.
- `/disclaimer` — scope of general educational information.
- `/content-policy` — copyright and takedown process.
- `/contact` — a real mailto-based contact route that clearly explains how it works.
- `/privacy` and `/terms` — conditional language that distinguishes current functionality from services enabled later.
- `/sitemap` — a user-facing HTML sitemap.

No personal qualifications were invented. The publisher is identified honestly as IdoréStudy Editorial, the independent creator and maintainer behind Idoré Collections, with a public contact address.

### Study room

The study room remains at `/study` and keeps the core functionality:

- 29 K-pop study buddies.
- Direct selection from a homepage query parameter.
- Custom study and break lengths.
- Start, pause, reset, and study/break switching.
- Browser-stored timer preferences.
- Browser-stored task list and completion progress.
- Optional music with **No music** selected by default.
- Café decorations.
- Buddy switching inside the room.
- Draggable and minimizable timer.
- User-initiated notification permission.
- Visible links to the selected third-party study-video and music sources.

The room contains no display-ad component or ad slot.

### Third-party media risk reduction

- Removed remote celebrity-photo hotlinks.
- Buddy cards use original text-and-color artwork generated by the interface.
- Media is not loaded on the professional homepage.
- The selected YouTube background uses the privacy-enhanced embed domain.
- Music is opt-in rather than loading a second media player automatically.
- The selected active room is marked `noindex` while the public `/study` lobby remains indexable.
- All 40 active media sources are listed in `MEDIA-SOURCE-REVIEW.md` for a required manual editorial review.

A disclaimer does not create media rights, and embedding a video does not by itself create sufficient publisher value. Remove or replace any source that is unavailable, unsuitable, misleading, or rights-unclear before applying.

### AdSense controls

Advertising is disabled by default and controlled through environment variables.

```dotenv
VITE_ADSENSE_ENABLED=false
VITE_ADSENSE_CLIENT=ca-pub-8850994665004292
VITE_ADSENSE_HOME_SLOT=
VITE_ADSENSE_RESOURCES_SLOT=
VITE_ADSENSE_GUIDE_SLOT=
```

When disabled, the publisher script and ad containers are not rendered. When enabled with real slot IDs, manual placements are limited to:

- The homepage after substantial original content.
- The complete Resources library.
- Long-form guide articles after substantive sections.

There are no coded display-ad placements in the study room, About, Contact, legal and policy pages, HTML sitemap, or 404 page. Keep Auto ads disabled initially or create exclusions for all interactive and non-content pages.

`public/ads.txt` contains:

```text
google.com, pub-8850994665004292, DIRECT, f08c47fec0942fa0
```

The ownership meta tag is also included in `index.html`.

### Consent and privacy configuration

A home-built cookie banner is not represented as a certified consent management platform. AdSense and analytics remain disabled unless explicitly configured.

Before serving Google ads to visitors in the EEA, United Kingdom, or Switzerland, publish an appropriate Google-certified CMP message through AdSense **Privacy & messaging**. Configure any applicable US-state message as well. The footer privacy-settings control is wired to Google’s revocation interface after the publisher script and account-side message are active.

### Optional analytics

Analytics is disabled by default:

```dotenv
VITE_ANALYTICS_ENABLED=false
VITE_GA_MEASUREMENT_ID=
```

It loads only when both variables are valid. Consent defaults are denied. Do not enable analytics until the real property and applicable consent flow are configured. Analytics is not loaded by the immersive study-room route.

### Performance and crawlability

- Public routes are lazy-loaded.
- The large study-room component is separated from the public-page bundle.
- Public pages do not request Google Fonts or remote artist images.
- Every fixed route and all 21 guide routes receive static HTML during the production build.
- Static pages include unique titles, descriptions, canonical URLs, one main heading, Open Graph metadata, and appropriate structured data.
- `robots.txt`, XML sitemap, HTML sitemap, manifest, favicon, social image, verification files, security headers, and a real noindex 404 document are included.
- Ad containers reserve space to reduce layout movement.

The generated XML sitemap contains 32 public URLs. Unknown paths should be served with a real HTTP 404 response, not a soft-404 rewrite to the homepage.

## Install, audit, and build

Use Node.js 20 or newer.

```bash
npm install
npm run audit
npm run build
```

`npm run check` runs the source/static audits and the full production build:

```bash
npm run check
```

The production output is written to `dist/`. The build process:

1. Regenerates `public/sitemap.xml` from the route registry.
2. Bundles React with Vite.
3. Generates route-specific static HTML.
4. Audits the generated HTML and internal links.

The stricter launch gate is:

```bash
npm run check:prelaunch
```

It deliberately fails while any active media source remains `Pending`, lacks a channel/rights basis, or lacks a review date.

For local development:

```bash
npm run dev
```

## Built-in verification

### `npm run audit`

Checks:

- JavaScript and JSX syntax.
- Relative import resolution.
- 21-guide catalogue parity.
- Minimum guide depth, section count, dates, and sources.
- 29 unique study buddies.
- 11 optional music choices plus the no-music default.
- Direct homepage-to-room links.
- Publisher/byline and trust-page signals.
- Ad isolation from the study room.
- Absence of remote artist-image hotlinks and external font imports.
- Sitemap and route parity.
- Static HTML titles, descriptions, canonicals, headings, bylines, internal links, external-link safety, 404 metadata, and route-split manifest expectations.

### `npm run audit:prelaunch`

Runs the full audit and then verifies every active media source against `MEDIA-SOURCE-REVIEW.md`.

## Deployment

### Vercel

- Build command: `npm run build`
- Output directory: `dist`
- Node.js: 20+

`vercel.json` includes security headers and route handling for the generated static pages.

### Netlify

Publish `dist/`. The files in `public/_headers` and `public/_redirects` are copied into the build. Unknown routes should use `dist/404.html` with a real 404 status.

### Other static hosting

Serve generated `route/index.html` files as directory indexes. Do not send `ads.txt`, `robots.txt`, `sitemap.xml`, verification files, or unknown paths to the React homepage with a `200` response.

## Required work outside the repository

Source code cannot complete these steps:

1. Finish all 40 rows in `MEDIA-SOURCE-REVIEW.md` and remove every rejected source from the data files.
2. Deploy the production build to the final canonical domain.
3. Confirm `ads.txt`, `robots.txt`, `sitemap.xml`, all policy pages, all guides, and the custom 404 are served correctly.
4. Add the domain in AdSense and complete ownership verification.
5. Configure and publish the applicable Google-certified consent message in AdSense Privacy & messaging.
6. Add the domain to Google Search Console, submit the sitemap, and request indexing for core pages.
7. Run PageSpeed Insights against the deployed site and correct any live Core Web Vitals regressions.
8. Build legitimate traffic and reputation over time. Domain age, backlinks, index history, and traffic quality are not code switches.
9. Keep ads disabled until approval and real manual slot IDs are available.
10. Recheck the live website immediately before requesting review.
